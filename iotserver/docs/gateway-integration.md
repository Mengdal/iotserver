# 工业网关接入规范（MQTT）

平台侧已实现网关接入服务（`internal/iotserver/core/application/gatewayingest`）。
本文档是对**网关厂商**的接口要求，网关按此实现即可接入平台，无需平台侧二次开发。

## 1. 连接参数

在平台「设备接入 → 网关管理」新增网关后，平台返回一次性接入信息：

| 参数 | 说明 |
| --- | --- |
| Broker | 平台 MQTT 地址（如 `tcp://<host>:58090`） |
| clientId | 网关 SN（全局唯一） |
| username | 网关 SN |
| password | 平台生成的一次性密钥（请妥善保存，界面不再回显） |

要求：MQTT 3.1.1 或 5.0，支持 QoS1、遗嘱（LWT）、断线重连。

## 2. 主题约定

网关 SN 作为主题中的唯一标识；`{sn}` 替换为实际网关序列号。

| 方向 | 主题 | 说明 |
| --- | --- | --- |
| 上行 | `iot/up/{sn}/data` | 实时数据（单条设备） |
| 上行 | `iot/up/{sn}/batch` | 断点续传批量补传 |
| 上行 | `iot/up/{sn}/status` | 心跳/状态（建议 30s 一次） |
| 上行 | `iot/up/{sn}/offline` | **遗嘱主题**：网关异常断线时由 Broker 代发 |
| 下行 | `iot/down/{sn}/config` | 平台下发采集/上报配置 |
| 下行 | `iot/down/{sn}/cmd` | 平台下发命令（restart / ota / sync） |

上行必须使用 QoS1；平台按 `(gatewayId, seq)` 去重，重发是安全的。

## 3. 上行报文格式

### 3.1 实时数据 `iot/up/{sn}/data`

```json
{
  "seq": 10231,
  "ts": 1735689600000,
  "deviceKey": "M-001",
  "productKey": "inj_01",
  "properties": {
    "temp": { "value": 23.5, "time": 1735689600000 },
    "rpm":  { "value": 1450 }
  },
  "events": {
    "alarm": { "eventTime": 1735689600000, "outputParams": { "code": "E01", "msg": "超温" } }
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `seq` | 建议 | 网关侧**单调递增**序号，平台据此幂等去重（强烈建议携带） |
| `ts` | 建议 | 报文时间（毫秒）。测点未带 `time` 时作为兜底 |
| `deviceKey` | 必填 | 网关内设备标识，需与平台「设备管理」里该设备的**网关内设备标识**一致 |
| `productKey` | 可选 | 产品标识，用于排查/后续自动注册 |
| `properties[].value` | 必填 | 属性值，类型与物模型一致（数值/字符串/布尔） |
| `properties[].time` | 建议 | **该测点的采集时间（毫秒）**，缺失时回落到 `ts` |
| `events[].eventTime` | 建议 | 事件发生时间（毫秒） |
| `events[].outputParams` | 事件有输出参数时必填 | 与物模型事件输出参数一致 |

> ⚠️ 时间戳是断点续传正确性的关键：**必须使用采集时刻，而不是发送时刻**。
> 平台按报文时间落库，补传的历史数据会出现在正确的历史位置。

### 3.2 批量补传 `iot/up/{sn}/batch`

断网期间网关本地缓存，恢复后成批补发。单包建议 ≤200 条 / ≤256KB。

```json
{
  "seq": 10232,
  "ts": 1735690000000,
  "records": [
    { "ts": 1735689600000, "deviceKey": "M-001",
      "properties": { "temp": { "value": 23.1, "time": 1735689600000 } } },
    { "ts": 1735689660000, "deviceKey": "M-001",
      "properties": { "temp": { "value": 23.4, "time": 1735689660000 } } }
  ]
}
```

- 每条记录的 `ts`/测点 `time` 是**原始采集时刻**；
- 同一包内可包含不同设备（`deviceKey` 不同）与不同时刻；
- 补传数据落库并参与历史查询；**不会触发告警规则回放**（离线期间的告警请在网关侧缓存为事件一并补传）。

### 3.3 心跳/状态 `iot/up/{sn}/status`

```json
{ "ts": 1735690000000, "online": true, "fw": "1.2.3", "ip": "10.0.0.9", "bufferPending": 123 }
```

- `online: false` 视为离线；
- `bufferPending` 为本地待补传条数，便于运维判断补传进度。

### 3.4 遗嘱 `iot/up/{sn}/offline`

连接时设置 LWT：`{ "online": false }`。平台收到即把网关标记为离线。

## 4. 下行报文格式

### 4.1 配置下发 `iot/down/{sn}/config`

```json
{ "type": "config", "version": 3, "config": { "collectInterval": 1000, "uploadInterval": 5000 }, "ts": 1735690000000 }
```

- 网关收到后应持久化并**回发 `status`**（或在下次心跳中带上当前 `version`）；
- 平台在网关管理页显示配置版本；网关上线后可用 `sync` 命令主动拉取最新配置。

### 4.2 命令 `iot/down/{sn}/cmd`

```json
{ "type": "restart", "ts": 1735690000000 }
{ "type": "ota", "payload": { "url": "http://...", "version": "1.3.0" }, "ts": 1735690000000 }
{ "type": "sync", "ts": 1735690000000 }
```

支持 `restart` / `ota` / `sync` 三种；未知类型应忽略并保持连接。

## 5. 平台侧行为

| 场景 | 平台行为 |
| --- | --- |
| 未注册的 SN 上报 | 拒绝并记录日志（防止任意设备注入数据） |
| `deviceKey` 未注册 | 拒绝该条并记录到网关上报日志（便于对账） |
| 重复 `seq` | 幂等丢弃，不重复写数据 |
| 收到数据 | 自动把网关置为在线并更新「最近上报时间」 |
| 数据落库 | 复用平台上行管道：写时序库 + 推送规则引擎（告警/场景/规则照常生效） |

## 6. 联调检查清单

- [ ] 用平台返回的 clientId/username/password 能连上 Broker
- [ ] `data` 主题发一条属性，平台「历史查询」能看到，且时间是报文时间
- [ ] 拔网线 5 分钟后恢复，缓存数据经 `batch` 补传后，历史曲线连续无断点
- [ ] 重复发送同一个 `seq`，数据不重复
- [ ] 断开网关电源，平台在 1 分钟内在网关列表显示离线（LWT 或心跳超时）
- [ ] 平台下发配置，网关收到并回执
